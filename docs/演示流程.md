# 当前版本演示流程

目标是在几分钟内展示数据接收、用户态校验、性能差异、RESET 后重新接收和正常卸载。使用已经部署匹配硬件、设备树及内核的板子；新 ko、zstream 已编译并放在当前目录。

命令依据当前源码及已有上板结果整理，本次未重新执行整套演示。流程不作为一次新增的测试通过记录，也不包含已移除的 test_fault 注入命令。

## 1. 加载并接收

开始时模块应尚未加载；若已经加载，先退出收发程序并正常卸载。

```bash
insmod stream_ctrl.ko
./zstream 100 --rate 0 --pkt-len 512
```

讲解：加载只建立资源；程序设置包长和间隔，START 安排接收。DMA 回调发布 READY，read 把一包复制给用户，程序逐字校验。

观察 `success=100 data_error=0 read_error=0 verify=on`，以及驱动 `errors=0 timeouts=0`。驱动接收包数可能多于 100，多出的已完成尾包在 STOP 时丢弃。

## 2. 对比有无校验

两次都读取 312500 包，每包 2048 B，共 640 MB：

```bash
./zstream 312500 --rate 0 --pkt-len 512
./zstream 312500 --rate 0 --pkt-len 512 --no-verify
```

讲解：数据量、包长和发送间隔相同，只改变用户态校验。已有三轮基线分别约 26.55 MB/s 和 84.65 MB/s；现场结果可能波动，按实际输出说明，不能承诺每次相同。按先前结果，两条命令合计约半分钟，运行中默认没有进度输出。

开启校验的吞吐包含检查内容的时间；关闭校验仅表示读到相应字节数。CPU 是整机忙碌率，不是进程独占 CPU 的比例。CSV 自动追加在当前目录，三轮重复的正式结论见[性能与稳定性记录](week11_性能记录.md)，现场一次输出不替代重复采样。

## 3. RESET 后重新接收

```bash
./zstream reset
./zstream 100 --rate 0 --pkt-len 512
rmmod stream_ctrl
```

讲解：reset 清理接收、复位数据源并清空事件历史，保持停止；之后新的 START 才重新接收。正常结束会停止预备新包、排空已领取的包，再完成清理。它展示控制流程，不当作一次新故障注入与恢复验证。

观察 reset 成功、再次 100 包校验通过，最后卸载没有报错。普通 rmmod 不带 `.ko` 后缀，按模块名使用。

## 4. 按需展示 trace

此步骤在前面正常卸载完成后使用：

```bash
insmod stream_ctrl.ko trace=1
./zstream 100 --rate 1000 --pkt-len 16
./zstream trace
rmmod stream_ctrl
```

挑一笔 rx_id，顺着事件解释：

```text
RX_BEGIN → SUBMIT → CONFIG/ISSUE_REQUEST → START_CMD
         → CALLBACK_READY → READ_TAKE → READ_DONE
```

这是同一包的逻辑顺序，不同包的事件会因流水线交错。预备下一包的 SUBMIT 可以早于上一包的 CALLBACK_READY；PREPARED 只代表已提交，实际 FPGA 启动对应 START_CMD。trace 只保留最近 128 条事件，不保证一包从最初事件起都还在。

## 5. 五分钟讲解提纲

1. **做什么**：FPGA 产生递增数据，AXI DMA S2MM 经 HP0 写入 DDR，Linux 驱动通过字符设备交付给用户。
2. **怎么组织**：四块 coherent 缓冲区依次轮换；DMA 接收、下一包预备和用户读取可以重叠，所有权由缓冲区状态表达。
3. **怎么通知和同步**：poll 报告事件，read 才取数据；io_lock 串行化用户操作，state_lock 保护与回调共享的状态；复制结束后内核缓冲区即可归还。
4. **怎么调试**：最重要的案例是新硬件配了旧 DTB；沿 Vivado → bitstream/XSA → DTS → DTB → 实际加载文件逐段定位，而不是只看编辑器中的源码。
5. **怎么评价结果**：三种包长、三种 rate、校验开关对照和 CSV 记录；2 KiB 包默认诊断关闭时，校验开启/关闭约 26.55/84.65 MB/s，是端到端程序基线，不是 DMA 硬件上限。
6. **怎么停止和收尾**：先禁止新任务，再排空或终止、同步回调、回收资源；已完成一小时以上持续接收、100 次启停、50 次加载卸载和运行中卸载拒绝测试。

当前版不做 mmap 或运行中设备解绑；明确保留静态设备、普通加载卸载的范围。临时故障注入来自早期学习版本，现版只保留实际实现的诊断和清理入口，不把 RESET 演示称作故障恢复实测。
