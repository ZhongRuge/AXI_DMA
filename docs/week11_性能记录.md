### 缓冲区与停止行为

- 包长组的 `discarded=4`、发送间隔组的 `discarded=2` 与当前流水线停止时丢弃预接收尾包的设计一致，不计入用户请求读取量。
- `full_pauses` 是因缺空闲缓冲区暂停的次数，不代表暂停总时长。2048 B、rate=0 时，开启校验约为 31.2 万次，关闭为 5～8 次；这反映消费节奏变化，不能直接换算成性能损失。
- 整机 CPU 忙碌率高低不能直接代表完成同样任务所花的总 CPU 时间，也不是 `zstream` 单进程的 CPU 占用。
- 这些结果建立了当前配置的重复测试基线，尚未测出 DMA 硬件上限；后续稳定性测试见下文 Week 12 记录。

## 测量口径

- `rx_ms`：START 前到最后一次接收、校验结束，包含用户态校验；不含 STOP 和 CSV 写入。
- `stop_ms`：仅统计 STOP ioctl 前后，排除结束时读取 CPU 统计的开销。
- `throughput_MBps`：`payload_bytes / 接收秒数 / 1000000`，MB 使用十进制单位。
- 开启校验时，`payload_bytes` 只累计通过校验的数据；关闭校验时，它只表示读取量，不证明内容正确。
- CPU 在接收窗口前后各读取一次 `/proc/stat`，采样窗口紧邻并略宽于吞吐计时窗口，不含 STOP。
- `cpu_busy_pct` 是**所有核心平均的执行忙碌率**，包含用户任务、内核任务、硬中断和软中断，也会受到其他系统负载影响。双核中一个核心全忙、另一个完全空闲时约为 50%。
- CPU 计算为 `Δ(user + nice + system + irq + softirq) / Δ(total) × 100%`；total 为前八列之和，不重复加入 guest/guest_nice。idle、iowait、steal 不算执行忙碌。
- CPU 时间按计数累计，不是纳秒。`cpu_ticks` 越少，百分比越粗糙；几十毫秒的短测不能用来精确判断 CPU 开销。没有有效计数变化或读取失败时，显示 `unavailable`，CSV 对应两列留空。

## CSV 字段

| 字段 | 含义 |
|---|---|
| `time_utc`、`build` | 写入时的开发板 UTC 时间、程序编译时间；开发板时钟可能未校准 |
| `packet_words`、`packet_bytes` | 包长，分别以 32 位数和字节为单位 |
| `target_packets`、`read_packets`、`success` | 请求包数、成功读取包数、通过校验的包数；关闭校验时 success 只表示读成功 |
| `rate_requested` | 明确传入的 rate；`-1` 表示沿用驱动配置，实际值未知，正式比较应显式指定 `--rate` |
| `verify`、`blocking`、`profile`、`trace` | 校验、阻塞读取、分段计时、事件记录开关；1 为开、0 为关，trace=-1 表示未能读取开关 |
| `payload_bytes`、`rx_ms`、`stop_ms`、`throughput_MBps` | 有效/读取字节数、接收时间、STOP 时间、吞吐；时钟异常时计时列留空 |
| `cpu_busy_pct`、`cpu_ticks` | 整机平均忙碌率、CPU 总时间的计数差；不可用时留空 |
| `data_error`、`read_error` | 用户态数据错误、读取或关闭错误计数 |
| `driver_rx_packets`、`discarded`、`full_pauses` | 驱动完成包数、完成后丢弃的包数、缺空闲缓冲区暂停次数；暂停次数不代表暂停总耗时 |
| `driver_errors`、`driver_timeouts` | 驱动错误、超时计数 |
| `stop_errno`、`stats_ok`、`run_ok` | STOP 错误码（成功为 0）、驱动统计是否读取成功、收发及计时检查是否通过且驱动错误/超时为 0 |

CPU 不可用不会冒充收发失败，单独看 CPU 列是否为空；`run_ok=1` 也不代表关闭校验的数据已验证。驱动统计读取失败时，驱动统计列留空，`stats_ok=0`、`run_ok=0`。

CSV 写入在计时结束后进行。写入失败会报错、退出码非零；已有文件表头不一致时拒绝追加。测试按顺序执行，同一个 CSV 不供多个进程同时写入。

### 本版采用的解绑策略

- 应用打开字符设备时，`file_operations.owner` 和 `cdev.owner` 使用 `THIS_MODULE`，由内核模块引用计数保护普通 rmmod；运行中卸载拒绝及退出后正常卸载已上板确认。
- 手动 sysfs `unbind` 与 rmmod 不同，原代码可能在应用仍保存 `filp->private_data` 时释放缓冲区及 devm 管理的设备对象。
- 按用户选择，在 `stream_ctrl_driver.driver` 中设置 `.suppress_bind_attrs = true`，关闭该驱动的 sysfs `bind/unbind` 入口。正常 insmod、自动匹配设备以及无打开句柄时的普通 rmmod 保留。
- 本版按静态板载设备使用，不实现运行中设备解绑或热移除的完整生命周期管理；关闭 sysfs 入口不等同于支持其他设备移除路径。
- STOP 先禁止新预备、等待工作与已领取的包，随后统一终止并同步，再回收缓冲区；read 交付受 io_lock 串行化，回调与共享状态受 state_lock 保护。本次未改动这些收发与清理逻辑，也未修改内核 DMA 驱动。
